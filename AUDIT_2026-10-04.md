# Local Notes audit — 4 October 2026

This audit covers the Android source and local test results through v0.7. It is not a security certification or a claim of perfect transcription. Models run on the phone and no account is required; the app needs internet access to download models. The original audio and editable transcript remain available when AI output is wrong or incomplete.

## Changes in v0.7

- Model archives now require a pinned SHA-256 checksum, HTTPS redirects, an explicit file allowlist, bounded archive entries, and a confined output path. A corrupt download is rejected before extraction. The hashes match the upstream release assets or model repository files listed below.
- Live audio waiting for inference is capped at 60 seconds. If processing falls behind, microphone capture continues to the saved PCM file, live text stops, and the saved audio is queued for a full accuracy pass after Stop. The same recovery is queued if the live engine fails and the accurate model is available. Pending work resumes when the app is opened.
- Cloud and device-transfer backup rules explicitly exclude private app data. Cleartext network traffic is disabled. Android's recent-apps snapshot is suppressed on supported versions, and copied transcripts are marked sensitive to hide clipboard preview on supported keyboards/system UI.

## Competitive position

| Capability | Local Notes v0.7 | Published competitor capability |
| --- | --- | --- |
| Free use | No account, subscription, API key, or minute quota; model downloads and phone storage are required | Otter Basic lists 300 transcription minutes/month; Plaud Starter lists 300 minutes/month with a bound device. Pocket advertises a free standard tier, so unlimited free use alone is not a unique advantage. |
| Privacy | Recording, transcription, speaker embeddings and summaries stay on the phone after models download | Cloud products have sync and cross-device features that this app does not. |
| Live text and names | Live draft, numbered speaker labels for completed turns, manual renaming within a recording | Otter lists live transcription and speaker identification; Pocket offers global speaker names and voice prints across recordings. |
| Capture and reach | OnePlus 13R microphone, Android only | Dedicated recorder microphones can capture differently. Otter supports iOS and Android. |
| Quality evidence | Two on-phone four-minute simulated meetings; normal final WER 11.59%, quiet (-26 dB) WER 11.07%, four voices detected and 43/44 turns labeled | No same-audio, same-condition competitor run, so there is no measured accuracy ranking. |

The major product gaps are cross-recording speaker identity, transcript search, an iOS client, and a validated several-hour test of the current release. The current 33-fact summary fixture also exposed omissions: detailed notes retained 25–26 facts and concise summaries 17–20. Summaries cannot promise zero information loss. The concise output should be treated as an overview, with detailed notes, editable transcript and audio for completeness. Accent and very low-volume accuracy are not established by the four-voice synthetic fixture; clipping, distance, overlap and noise can erase acoustic information that software cannot reconstruct.

## Security review and limits

Reviewed the manifest, network/download path, private file storage, backup rules, exports, logging, native dependency pins, and processing queues. Only MainActivity is exported; recorder/download/processing services are private. The app does not use a WebView, embedded API key, or app server. Export and Android share/clipboard actions are user initiated. No recording text is logged by the app's performance logs. Model files are still native parser inputs, so pinning hashes reduces untrusted-input exposure but cannot prove that native libraries have no vulnerabilities. Existing models installed before v0.7 have a legacy completion marker and are checked for required files, not retroactively checked against their original archive hash. Deleting and re-downloading a model applies the new hash check.

Recordings are in Android app-private storage but are not separately encrypted with a user password. Anyone with access to an unlocked or compromised phone, or a ZIP the user exports, can potentially read them. Marking clipboard content sensitive hides the preview; it does not prevent a recipient app from reading content that the user shares or pastes. Backups are disabled and explicitly excluded from Android transfer, but an OEM-specific path was not independently verified on every device. No source audit can honestly promise that code has no exploitable flaw.

## iOS feasibility

sherpa-onnx has an iOS/Swift build path, but this repository is an Android/Kotlin/Compose/AudioRecord app with an Android JNI summary bridge. An iOS release needs a separate client for recording, background audio, storage, interface, downloads, and a compatible on-device summarizer. There is no Mac with Xcode or iPhone available, so an iOS binary cannot be built or microphone-tested in this project now. The Android APK does not run on iOS.

## Validation and next acceptance test

The v0.7 host run passed 25 unit tests, Android lint analysis and both APK builds. On the OnePlus 13R, a 4:04 four-voice synthetic replay produced 56 refined segments, 11.59% final word error, 300 ms median/1,000 ms maximum live lag, and no crash. Four known voices were mapped consistently across 43/44 turns; one one-second fragment received a spurious fifth label. The transcript finished about 1.9 seconds after capture; the optional smaller Qwen summary job took 71.9 seconds. That summary retained 17/33 predefined facts and detailed notes 22/33, reinforcing the choice of Gemma as the default. The signed minified release was installed over v0.6 and launched. Current-release several-hour real microphone capture, diverse natural accents, far-field/low voices and a same-fixture Pocket/Otter comparison remain untested. A good next benchmark is consented real English speech from several speakers and accents, measured word error and speaker attribution at near/normal/far distances, with phone temperature, battery, storage and live latency logged over a 3–4-hour session.
